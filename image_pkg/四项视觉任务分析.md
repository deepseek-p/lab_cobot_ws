## V1：ArUco 视觉抓取闭环

### 已完成的实际流程

2026-08-07 以 `aruco_sample` 执行中文指令 `把样件从A送到B`，运行参数为：

- `use_gazebo_model_pose=false`：使用相机 ArUco 图像位姿，不用 Gazebo 真值替代视觉结果。
- `use_wrist_detect=true`、`use_refine_detect=true`：先由腕部相机观察，再在预抓取位置进行二次修正。
- `use_tactile_grasp=true`：以触觉夹爪插件的实际附着消息作为抓取成功条件。

实际事件链如下：

```text
NAV_TO_PICK
→ A 工位地图精停和视觉停靠
→ wrist_detect=hit
→ refine=hit
→ attached aruco_sample
→ 抬升和离站退避
→ NAV_TO_PLACE
→ B 工位停靠
→ release accepted
→ RETURN_HOME
→ DONE
```

首次失败不是视觉检测问题：`aruco_sample` 曾设为静态模型，夹爪插件会跳过静态场景物，导致 `refused none no_candidate_model`。已将 `lab_cobot_gazebo/models/aruco_sample/model.sdf` 改为 `<static>false</static>`，重启后 Gazebo `/gazebo/get_model_properties` 返回 `is_static=False`，随后得到 `attached aruco_sample` 并完成全流程。

结论：ArUco 样件的“初次定位 → 转 `base_link` → 靠近 → 二次观察修正 → 抓取 → 搬运 → 放置”已完成仿真验证。该结论不外推为所有八类 YOLO 目标均可抓取。

## V2：三维定位与精度

- `image_pkg` 使用自训练八类 YOLO 检测框与 RGB-D 有组织点云计算三维位置，并发布到 `base_link`/`odom` 评测坐标系。
- ArUco 路径通过腕部相机提供近距离二次观测；本次抓取中首次二次修正量约为 `( +1, -1, 0 ) mm`。
- 该修正量只说明两次视觉观察的一致性，**不能**作为末端或工件达到 1 mm 定位精度的证明。
- 1 mm 验收应仅在 `attached aruco_sample` 后，以 TCP TF 和 Gazebo 工件真值在同一 TCP 局部坐标系计算相对位姿误差；该专项统计仍待补齐。

## V3：六种光照/遮挡工况

- 已修复同坐标系真值转换、相机源时间戳门控和逐物体观察门控，避免跨工位延迟帧被错误计入下一站。
- 正常光 C1 的逐物体观察复测中，`aruco_sample` 有 29 个有效三维样本，平均误差约 `0.0185 m`；其他类别仍存在二维漏检或三维转换系统偏差。
- C2–C6 尚未以同一权重、同一观察策略和同一误差阈值完成可比测试。因此 V3 当前只能说明 C1 流程已可运行，不能说明六种环境识别率已经达标。

完整数值、XYZ 误差和各次复测结论见 [`lighting_test_report.md`](lighting_test_report.md)。

## V4：设备状态识别

- `indicator_state` 节点可依据图像 ROI 的红/黄/绿灯颜色发布 `/perception/device_states`。
- 状态语义为：绿 `running`、黄 `idle`、红 `fault`；颜色不明确或多灯竞争时输出 `unknown`。
- 当前仿真模型尚未提供“仅单灯亮”的可切换状态，也没有完成与巡检任务消费端的端到端验证，因此 V4 仍是可用感知接口而非已验收任务。
